# Frontend Mainline Plan

## 产品阶段（2026-06-03 重定义，以根 `CLAUDE.md` §2 为权威）

1. Phase 1：底层加固（客户端，开发中；主仓 `ZDaMexy/oms`，不在本前端仓库范围）
2. Phase 2：初版官网 — 无登录的 OMS 官网（**本仓库承载，当前工作**）
3. Phase 3：OMS-IR — 注册账号，客户端内登录/传分/排行（也许支持 LR2 / RAJA 本地存档分数上传）
4. Phase 4：社区官网 — 像 osu!(official) 那样的中心化社区官网
5. Phase 5：开放接口 — API 与外部接通、QQ bot、非 OMS 客户端向 OMS-IR 传分等

> 旧模型「宣传展示→账号→主页成绩→排行榜→谱面下载」已废弃。本仓库的 `subline/P1-A`（首版静态宣传页工作线）实际对应新模型的 **Phase 2「初版官网」**，编号沿用历史不改名。

## 阶段计划（前端视角）

### Phase 2：初版官网（本仓库当前工作）

- 纯静态 HTML/CSS/JS 官网，单页 `index.html`；不预先引入框架或构建系统
- 完成产品介绍、特性表、判定窗口、路线图、下载方式等首页分区与锚点
- 下载方式：GitHub Releases / QQ 群一键加群静态跳转（不经 Web 后端）
- 信息架构为后续账号、主页、排行榜、社区等动态页面预留导航与扩展位
- 逐项向用户确认正式文案、展示媒体、外链；阿里云 ECS + Nginx 部署

### Phase 3：OMS-IR（前端侧）

- 注册 / 登录页与账号入口；玩家主页、成绩列表、单曲表现、EX-SCORE、排行榜视图
- 对接 `oms-backend` 的认证与 OMS-IR 接口（登录、传分、排行）

### Phase 4：社区官网

- 参考 osu!(official) 的中心化社区门户，整合账号 / 成绩 / 榜单 / 谱面入口

### Phase 5：开放接口（前端侧）

- 配合开放 API / QQ bot / 外部客户端传分生态的页面与文档入口

> Phase 1「底层加固」为客户端侧工作（BMS ruleset / mod / 游玩 / 皮肤 / 性能优化），由主仓 `ZDaMexy/oms` 承载，不在本前端仓库范围。

## 当前最近任务

- 保持 Phase 1 的宣传展示目标不偏离完整产品路线
- 落地首版静态展示与宣传页骨架
- 形成首轮内容确认清单，并以逐项提问方式向用户确认页面内容
- 固定前端文档、前后端桥文档与客户端快照桥文档之间的联动规则
- 在页面结构中为账号、主页、成绩、排行榜和下载入口保留导航与页面扩展位
